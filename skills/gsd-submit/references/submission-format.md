# 제출물 형식

노션 `[GSD] ODL 지팡이 가이드` 의 샘플 프로젝트가 기준이다. 40기부터 이 형식으로 올라가 있다.

형식을 지키는 이유는 단순하다. 제출물은 **다른 참가자들이 구경하는 화면**이다.
같은 시간을 들여 만들었어도 평문 몇 줄이면 초라해 보이고, 섹션이 잡혀 있으면 만든 것이 제대로 보인다.

## 섹션 구성

```markdown
## 💡 서비스 개요
**한줄 요약:** 무엇을 하면 무엇이 되는지 한 문장.

## 🔗 프로젝트 URL
[서비스 바로가기](https://my-app.vercel.app)

## ✨ 핵심 기능
**1. 기능 이름**
무엇을 어떻게 하는지 2~3문장.

사용 예시: "실제로 이렇게 씁니다"

**2. 두 번째 기능**
- 📊 세부 항목
- 📈 세부 항목

## 🛠 기술 스택
- AI 모델: Claude
- DB: Supabase
- 호스팅: Vercel
- AI 코딩: Claude Code

## 📝 회고
**배운점:** 오늘 실제로 배운 것.

**다음 단계 계획:** 이걸 앞으로 어떻게 할지.
```

`##` 는 섹션 제목, `###` 은 그 아래 소제목이다. 마크다운으로 쓰면 `md-to-tiptap.mjs` 가 변환한다.

## 쓸 때 지킬 것

**작업 기록에 있는 것만 쓴다.** 만들지 않은 기능을 그럴듯하게 채우지 않는다.
제출물을 보고 실제로 서비스를 열어보는 사람이 있다.

**회고를 대충 쓰지 않는다.** 이 섹션이 이 형식의 핵심이다.
"AI 코딩이 편했습니다" 같은 말 말고, 그날 실제로 막혔던 지점과 어떻게 풀었는지를 쓴다.
`session-digest.mjs` 의 요청 시간순 목록을 보면 어디서 반복해서 헤맸는지 그대로 보인다.

**한줄 요약은 기능이 아니라 결과를 쓴다.**
"BigQuery에 SQL을 날립니다"가 아니라 "채팅으로 묻기만 하면 분석 리포트를 만들어줍니다".

**기술 스택에 `AI 코딩: Claude Code` 를 빠뜨리지 않는다.** GSD 제출물의 관례다.

**이모지는 섹션 제목과 불릿에만.** 문장 안에 흩뿌리면 읽기 어렵다.

## summary (목록에 뜨는 소개)

`description` 과 별개로 2~3문장짜리 `summary` 가 있다. 현황판 목록과 카드에 보이는 글이다.
서비스 개요의 한줄 요약을 풀어 쓰되, 마크다운 없이 평문으로 쓴다.

> 마케팅 AI 분석 에이전트는 복잡한 마케팅 성과 데이터를 누구나 쉽게 조회하고 인사이트를 얻을 수
> 있도록 돕는 대화형 AI 서비스입니다. 데이터 분석가에게 리포트를 요청하거나 어려운 SQL 쿼리를
> 직접 작성하지 않아도 됩니다.

## 팀명과 주제

| 필드 | 무엇을 넣나 | 예 |
|---|---|---|
| `teamName` | 만든 사람 이름 (혼자 참가가 대부분) | `김채은` |
| `title` | 제출물 주제 = 서비스 이름 | `마케팅 AI 분석 에이전트` |

`title` 에 "AI로 만든 ○○ 서비스" 같은 수식을 붙이지 않는다. 목록에서 잘린다.

## 기준 샘플 (40·41·42기에 등록된 것)

```markdown
## 💡 서비스 개요
💬 **한줄 요약:** 채팅으로 묻기만 하면, AI가 사내 광고 성과 DB에 직접 접속해 분석 리포트를 만들어줍니다.

## 🔗 프로젝트 URL
[https://marketing-ai-agent.vercel.app/auth](https://marketing-ai-agent.vercel.app/auth)

## ✨ 핵심 기능
**1. 자연어 질의응답 (Chat to SQL)**
사용자의 자연어 질문을 AI가 이해하여 자동으로 Google BigQuery 환경에 맞는 SQL 쿼리를 생성 및 실행합니다. 분석된 결과는 알기 쉬운 요약 리포트 형태로 즉시 제공됩니다.

사용 예시: "이번 달 메타 광고 캠페인별 노출수, 클릭수, 전환수 정리해 줘."

**2. 원클릭 성과 리포트 프리셋**
마케터들이 가장 자주 확인하는 필수 분석 항목들을 클릭 한 번에 조회할 수 있는 '프리셋 질문' 기능을 제공합니다.

- 📊 기간별 성과 리포트: 주간/월간 매체별 광고비 및 ROAS 요약
- 📚 매체별 비교 분석: 구글, 메타, 네이버 등 채널별 전환 단가(CPA/CAC) 비교
- 📈 캠페인 성과 분석: 성과(ROAS)가 가장 우수한 상위 캠페인 추출
- 🎯 퍼널 분석: 각 마케팅 단계(노출 → 클릭 → 전환)별 행동 전환 비율 추적
- ⚠️ 이상치 감지: 광고비 급등 리스크나 클릭률(CTR) 급락 등 특이점 즉시 확인

**3. 투명한 데이터 검증 및 안전한 접근**
AI가 작성한 원본 SQL 쿼리 코드를 직접 열람하고 복사할 수 있습니다. 원본 마케팅 데이터는 조회 전용(Read-Only)으로 처리되므로 데이터 훼손 위험이 없습니다.

## 🛠 기술 스택
- AI 모델: Gemini 3.5 Flash
- DB: Supabase
- 인증: NextAuth (Google SSO)
- 호스팅: Vercel + Supabase
- AI 코딩: Claude Code

## 📝 회고
**배운점:** AI 코딩으로 비개발자도 실제 서비스를 만들고 배포할 수 있다는 걸 체감했습니다. 특히 프롬프트를 잘 쓰는 게 중요하다는 걸 느꼈어요.

**다음 단계 계획:** 실제 사내 데이터를 연동해서 팀원들이 쓸 수 있는 내부 툴로 발전시킬 계획입니다.
```

## 지원하지 않는 것

`md-to-tiptap.mjs` 는 헤딩·문단·불릿·굵게·기울임·링크만 다룬다.
표, 인용, 이미지 삽입, 코드 블록은 변환하지 않는다 — 제출물에 필요했던 적이 없다.
표를 꼭 넣어야 하면 불릿으로 바꿔 쓴다 (원본 샘플의 기술 스택 표도 그래서 불릿이다).
